Spotifast PR #845: Play local files from chosen folders

Change: play local MP3, M4A and FLAC files chosen in Settings. Baseline: main at fc60826, candidate: this branch (10 commits, ends at 960e305). Captures produced by demo mode (--demo-shot) on Windows 11 x86_64; window sizes 1280x800 (normal), 900x700 (narrow) and 1280x1440 with the same scripted scroll for the Settings view. The same demo data drives both builds. Linux and macOS were not captured here; CI builds and tests them.

What the change looks like

  • Settings grows a third section, Local files, between Playback and Appearance: an on/off switch, an Add a source button, and the chosen folders, each removable. Off, the section is just the switch.
  • The library sidebar gains a Local files entry with the song count, and the entry opens a page of the scanned files with title, artist, album and duration.
  • A playing local file shows its name and artist in the player bar and its embedded cover art; a file with no embedded picture shows the placeholder.
  • Demo tracks deliberately carry no embedded art, so demo rows show the placeholder; real files with embedded art show it (covered by tests and a real-library scan).

Checks

  • Run locally on Windows x86_64, all green: cargo fmt --all --check; cargo clippy --locked --all-targets -- -D warnings and the same with --all-features; cargo test --locked --all-targets and the same with --all-features; cargo test --locked --all-features --doc; RUSTDOCFLAGS='-D warnings' cargo doc --locked --all-features --no-deps. Translation catalogs were regenerated with .github/scripts/update-translations.sh.
  • Also run locally: a scan of a real library of 1452 files, matching the count Spotify Desktop reports for the same folders; 1450 files show their embedded cover (two MP3s carry 9-11 MB PNG art over the 8 MB cap and use the placeholder).
  • Left to CI: the Linux and macOS suites, the docs (Jekyll) build, the Nix build, packaging/test-launchers.py and update-translations.sh --check.
